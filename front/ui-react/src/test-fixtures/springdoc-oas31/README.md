# Springdoc OpenAPI 3.1 acceptance fixtures

These snapshots are generated by the repository's real smoke applications:

| Snapshot                             | Runtime               | Springdoc mode                   |
| ------------------------------------ | --------------------- | -------------------------------- |
| `boot3-mvc-springdoc-2.8.9.json`     | Spring Boot 3 MVC     | explicit `OPENAPI_3_1`           |
| `boot3-webflux-springdoc-2.8.9.json` | Spring Boot 3 WebFlux | explicit `OPENAPI_3_1`           |
| `boot4-mvc-springdoc-3.0.3.json`     | Spring Boot 4 MVC     | default and explicit OpenAPI 3.1 |

The corresponding Java smoke tests own the generator setup and compare the live
`/v3/api-docs` response to these files. The only normalization is the random
server URL, replaced with the equivalent current-origin URL `/`, so the exact
snapshot can also be served by Knife4x. A Springdoc version change must therefore
review the complete snapshot diff explicitly.

Springdoc 2.8.9 emits a generic Java `Object` as `type: object`, while
Springdoc 3.0.3 leaves that schema typeless. Both versions expose positional
`prefixItems`, but do not retain the Java annotation's nested tuple types. The
real snapshots also keep the generated optional `limit` query Parameter Object
next to a GET request body. The standards-valid
`browser-supplement-3.1.2.json` fixture covers that
non-expressible typed tuple, Reference Object siblings, webhooks, and a denied
external resource without attributing those shapes to generated output.
